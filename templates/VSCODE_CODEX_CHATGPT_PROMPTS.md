# VS Code × Codex × ChatGPT 用プロンプト集

対象: Expo / React Native / TypeScript / GitHub を使うアプリ開発。

- ChatGPTからCodexへの情報は常に自動同期されるわけではないので、計画をコピーし、関連資料の場所を指定する。
- 各リポジトリの実際のpackage.json・AGENTS.md・Gitの状態を優先する。
- ［ ］ を埋め、1回の依頼を小さな機能に限定する。
- 本番変更、マージ、課金、秘密情報の取り扱いは別途承認する。

## 1. ChatGPT向け：次の1PRを設計する

~~~text
対象プロジェクト: [名称]
やりたいこと: [機能 / 不具合]
技術スタック: [例: Expo SDK 58 / React Native / TypeScript]
既存の関連資料: [GitHubリポジトリ、仕様書、HANDOFF.mdなど]

次の項目を整理してください。
1. 現状の情報と未確認事項（推測を事実としない）
2. 1PRで完了する最小タスク
3. 実装範囲と対象外
4. リスクと戻し方
5. 完成条件（Done when）
6. VS CodeのCodexに渡す実装プロンプト

設計のみ作成し、実装はまだ行わないでください。
~~~

## 2. VS CodeのCodex向け：選択範囲だけ修正

~~~text
現在開いているファイルと選択範囲を確認してください。

目的: [期待動作・解消したい問題]
変更対象: 選択した部分と、それに不可欠な関連箇所のみ
変更禁止: [既存の公開API、他画面、依存関係など]

まず関連する呼び出し元・テストを調べ、
最小の変更を行ってください。

型チェック、Lint、関連テストを実行し、
差分、検証結果（PASS / FAIL / 未実施）、
残るリスクを報告してください。
~~~

## 3. VS CodeのCodex向け：機能を安全に実装

~~~text
Gitの現在のブランチ・差分、AGENTS.md、関連仕様を確認してください。

実装内容: [1機能]
背景: [対象画面や既存データ]
対象外: [今回作らない機能]
完成条件:
- [UIまたはAPIの動作]
- [型チェック・Lint]
- [関連テスト]
- [実機確認が必要なら、その確認項目]

ルール:
- 必要最小限のファイルだけ変更
- 無関係なリファクタリングや依存追加をしない
- 機密情報をログ・Gitに含めない
- mainへの直接Push、本番DB変更、デプロイ、マージをしない

最初に変更予定を簡潔に示してから実装し、
検証して差分を確認してください。
最後に変更ファイルと未検証項目を報告してください。
~~~

## 4. VS Code / Codex向け：レビューのみ

~~~text
今のGit差分を読み取り専用でレビューしてください。
コードや設定は変更しないでください。

確認項目:
- バグ・退行・境界条件
- TypeScriptの型安全性
- セキュリティと秘密情報
- 依存追加、不要な変更、仕様との不一致
- テスト不足、未確認の画面/デバイス

重大度順に、対象ファイル、問題の理由、
再現方法、推奨修正を報告してください。
指摘がない場合もレビューの限界を明記してください。
~~~

## 5. ChatGPT向け：PR結果を判断する

~~~text
対象PR: [URL]
必要な情報: [最新のGitHubの差分・Actions・Preview・HANDOFFなど]

PRの状況を確認し、次の形式でまとめてください。
- 変更内容と目的
- 検証済み / 失敗 / 未確認
- リスクと既存機能への影響
- 手動で確認すべきこと
- マージ可能と判断するために不足する条件

CI成功と実機動作確認は分けてください。
根拠のないPASS判定や自動マージはしないでください。
~~~

## 6. 長期作業の引き継ぎ

~~~text
最新のブランチ、PR、差分、CI結果と
既存のWORKLOG.md / HANDOFF.mdを照合してください。

次の項目を残してください。
- 現在地、重要な決定、完了済みの作業
- 未完了と未検証の事項
- 次回の最小タスクと着手条件
- 変更禁止事項とロールバックの方針

既存の引き継ぎファイルを使い、
似た目的の新しい記録ファイルは増やさないでください。
~~~

## 使い方

1. ChatGPTで **1. 設計**。
2. VS CodeのCodexで **2. または 3. 実装**。
3. VS Codeで差分を確認し、Codexで **4. レビュー**。
4. GitHub Actions・Preview・必要な実機検証の結果とともに **5. PR判断**。
5. 作業が複数日にわたる場合は **6. 引き継ぎ**。
