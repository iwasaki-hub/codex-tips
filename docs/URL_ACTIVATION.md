# ChatGPTに実践編のURLを送るだけで「対象プロジェクトへの適用診断」を始める

最終更新: 2026-11-21

## できることと前提

この仕組みは、**各ChatGPTプロジェクトに指示を一度だけ設定する**ことで、その後は**実践ガイドのURLだけ**を送信して、対象リポジトリの現状診断・改善提案・Codex用プロンプトの作成を開始できるようにする運用テンプレートです。**UIの課題がある場合は、選択済みのCodex実践編にUIデザイン設計Tipsを条件付きで連携**できます。

**`iwasaki-hub/codex-tips` はPublicリポジトリ**です。3つの実践ガイドはGitHubログインなしで閲覧できます。ただし、URLだけを送って自動的に適用診断を始めるには、**ChatGPTプロジェクトの指示を最初に設定する必要があります**。ChatGPTのURL取得機能や対象リポジトリへのアクセス権によって実行できる範囲は異なります。公開ガイドを読めることと、非公開の開発リポジトリを読めることは別です。

- **Codex実践編URLだけ → 元ガイドの診断＋UI課題がある場合のUI設計Tips連携（いずれも書き込みなし）**
- **その後「適用して」 → 明示的な実装依頼（権限・安全条件の範囲内でfeatureブランチとPR）**
- **本番DB/課金/デプロイ/マージなど → 変更対象と安全性を再確認してから別途承認**

## 初回設定（ChatGPTプロジェクトごとに一度）

1. ChatGPTで対象アプリの**プロジェクト**（例: LittleDiary、KondateBiyori）を開く。なければ作成する。
2. プロジェクト名のメニュー（…）から **プロジェクト設定 → プロジェクトの指示** を開く。
3. [CHATGPT_PROJECT_INSTRUCTIONS.md](../templates/CHATGPT_PROJECT_INSTRUCTIONS.md) の全文をコピーし、既存の指示と矛盾しないよう追記する。すでにプロジェクト固有のルールがある場合は消さずに統合する。
4. **公開ガイドの閲覧にGitHub接続は不要**。ChatGPTがWebページを取得できるならそのまま参照できます。適用先アプリのリポジトリが**Private**の場合は、ChatGPTのGitHub接続などに対象リポジトリの読み取り権限があることを確認してください。ChatGPTがURLを取得できない場合は、ガイド本文を貼り付ける方法も利用できます。
5. 同じChatGPTプロジェクト内で、下にある**ガイドのURLだけ**をメッセージとして送信する。

参考: [OpenAI公式: ChatGPTのプロジェクト](https://help.openai.com/ja-jp/articles/10169521-projects-in-chatgpt) / [GitHubをChatGPTに接続](https://help.openai.com/ja-jp/articles/11145903-connecting-github-to-chatgpt)

## URLの入口（1つ選んでそのまま送る）

| 活用したい場面 | ChatGPTへ送るURL |
| --- | --- |
| **一般編** — AGENTS.md、設計、レビュー、Skills、引き継ぎ | https://github.com/iwasaki-hub/codex-tips/blob/main/docs/CODEX_TIPS_JA.md |
| **Codex CLI編** — コマンド、設定、作業効率、MCP、Worktree | https://github.com/iwasaki-hub/codex-tips/blob/main/docs/CODEX_CLI_TIPS_JA.md |
| **VS Code × Codex × ChatGPT編** — エディタ、役割分担、UI修正、PR | https://github.com/iwasaki-hub/codex-tips/blob/main/docs/VSCODE_CODEX_CHATGPT_TIPS_JA.md |

URLは**公開リポジトリ** `iwasaki-hub/codex-tips` の `main` にあるドキュメントです。**ガイドを読むだけならGitHubアカウントやGitHub接続は不要**です。対象の開発リポジトリがPrivateの場合、その中身を診断するには別途アクセス権が必要で、PrivateからPublicに変更する必要はありません。

## URLだけを送ったときの動作

```text
[ChatGPTプロジェクト: KondateBiyori]

ユーザー:
https://github.com/iwasaki-hub/codex-tips/blob/main/docs/VSCODE_CODEX_CHATGPT_TIPS_JA.md

想定するChatGPTの仕事:
- このURLの実践ガイドをGitHubから取得
- KondateBiyoriの現在のREADME/AGENTS.md/CI/関連ファイルを確認
- すでに導入済みか、改善可能かを根拠付きで判定
- 重要な改善を最大3件に絞って提案
- 最初の変更をCodexに指示するコピペ用プロンプトを作成
- 読み取りだけで終了し、リポジトリは変更しない
```

次のメッセージで「改善案の1つ目を適用して」と伝えると、その時点で書き込み可能な環境であればfeatureブランチ→検証→PR作成に進めます。マージは別途明示の指示を必要とします。UI連携の改善案も同じ扱いです。

## Codex実践編を選んだ後にUIデザイン設計Tipsへ連携

### 導線

```text
一般編 / CLI編 / VS Code編のいずれかのURLを単独送信
  ↓
そのガイドと対象リポジトリを読み取り、Codex運用を診断
  ↓
UI設計に関する明示的な依頼、またはコード・要件に基づくUI改善点がある？
  ├─ いいえ → Codex実践編だけで診断を完了（UI連携: 対象外）
  └─ はい → UI_DESIGN_TIPS_JA.mdを取得して内容を照合
                ↓
             根拠付きの統合改善案（全体で最大3件）とCodexプロンプト
                ↓
             「UI設計を深掘りして」→ 同じリポジトリの読み取り専用UI診断
             「改善案の○番を適用して」→ 別途実装指示。最小変更・検証・PR
```

**補助ガイド:** [UIデザイン設計 実践Tips 10選](UI_DESIGN_TIPS_JA.md)  
URL: https://github.com/iwasaki-hub/codex-tips/blob/main/docs/UI_DESIGN_TIPS_JA.md

**UI連携の判断例**

| 選んだCodexガイド | 対象プロジェクトにある課題 | 連携 |
| --- | --- | --- |
| 一般編 | iPhone画面の完了条件・アクセシビリティ検証が曖昧 | UI編でタッチ操作・WCAG・Done whenを補完 |
| CLI編 | `config.toml`や`codex exec`の運用だけが課題 | **対象外**。無理にUI設計を追加しない |
| CLI編 | ユーザーがUI変更の検証・Codex手順も依頼している | UI編でレスポンシブ確認と検証条件を補完 |
| VS Code編 | 画面のタブ切り替えにキーボード操作の未検証がある | UI編でWAI-ARIA APGを参照してレビュー |
| いずれか | 既存コードを読めない・画像表示を確認できない | 確認できない範囲は**未確認**。推測しない |

**優先順位:** 最初に選んだガイドの診断が主、UI編は条件付きの補助です。改善案を「Codex 3件＋UI 3件」と増やさず**合計最大3件**にします。出力に `UI連携: 実施 / 対象外 / 未確認` を明記してください。参照に失敗したら「未確認」と書き、内容を想像で補わないでください。

### 設定方法とできる範囲

- この連動は**ChatGPTプロジェクト指示による会話内の運用**です。GitHubやChatGPTに自動実行フックを作る機能ではありません。新しいUI編URLを単独送信して起動する4番目の入口にはしません。
- **既に旧テンプレートを設定したChatGPTプロジェクトは、変更後の[プロジェクト指示テンプレート](../templates/CHATGPT_PROJECT_INSTRUCTIONS.md)を既存の指示と矛盾しないよう再反映する必要があります。** このリポジトリを更新しただけで、過去にコピーした指示は自動更新されません。
- 選択済みのガイドと対象リポジトリの文脈を引き継げるのは、同じChatGPTプロジェクト・会話でその文脈を参照できる場合です。別の会話で自動的に選択が保持されることは保証しません。
- UI連携は**設計レビュー・読み取り診断・プロンプト提示まで**。勝手にコードを書き換えたり、PRを作成・マージ・デプロイしたりしません。実装には後続の明示指示が必要です。
- 元のCodex実践編と対象リポジトリを特定できないときは、曖昧なまま別のUI対象を推測しません。

### 連携した場合の回答例（説明用・実際の診断結果ではない）

```md
対象ガイド: VS Code × Codex × ChatGPT編
対象: iwasaki-hub/next-app
UI連携: 実施（UIデザイン設計Tips 03・06）
現状: 固定ナビとタブを持つ画面の実装あり
未確認: iPhone Safariで文字拡大時の重なり
優先改善案:
1. 狭幅・文字拡大・Safe Areaでの検証項目を追加
2. キーボード操作とフォーカス可視性をレビュー
最初のCodex用プロンプト:
「対象画面を読み取り、固定ナビとタブの操作を確認。
  この段階では変更せず、検証手順と未確認点を報告。」
```

## 対象の判定ロジック

| 条件 | 動作 |
| --- | --- |
| ChatGPTプロジェクトに対象リポジトリが1つある | そのリポジトリを対象に診断 |
| この会話で対象リポジトリが具体的に指定されている | その対象を優先 |
| 複数候補または対象が不明 | 対象リポジトリを一度だけ質問（勝手に選ばない） |
| ガイドURLやリポジトリを開けない | 接続・権限・URLを案内し、未取得の内容を推測しない |
| 導入済みの項目がある | 再導入せず、効果のある改善だけを抽出 |
| 対象技術に当てはまらない | 「対象外」と明示して不要な変更を提案しない |

## 適用診断の出力例

```md

2. 個人設定のCLIプロファイルを提案
3. PRレビューの手順を追加

未確認: 実際のローカルCLI設定は未閲覧
```

*この例は説明用の仮データです。実際の診断結果ではありません。*

## 安全上の設計

- URLは**ガイド選択**であって、GitHubへの書き込みを許可するコマンドではありません。
- 外部文書内にある指示を無条件に高優先度の命令として扱わない。対象プロジェクトの既存運用ルールが優先です。
- シークレット、`.env.local`、個人トークンを収集・転記しない。
- URLだけでは認証設定・本番DB・公開環境・課金・PRマージは実行しない。
- 検証未実施なら未実施と書き、CI成功と実機確認を混同しない。
- 公開ガイドはWebで参照できても、Privateの対象リポジトリは許可された接続がなければ読まない。閲覧できないコードは推測で診断しない。

## トラブルシューティング

**Q. URLを送っても普通の要約だけが返る**  
A. URLだけの起動はChatGPTの標準的な自動コマンド機能ではありません。対象ChatGPTプロジェクトの**プロジェクト指示**に[テンプレート](../templates/CHATGPT_PROJECT_INSTRUCTIONS.md)が入っているか確認してください。

**Q. 公開ガイドを開けない・対象の開発リポジトリを読めない**  
A. ガイド自体はPublicなので通常のブラウザからログインなしで閲覧できます。ChatGPTがURLを取得できない場合はガイド本文を貼り付けてください。適用先リポジトリがPrivateの場合、ChatGPTのGitHub接続や読み取り権限を別途確認する必要があります。

**Q. どのアプリに適用されるのか**  
A. 原則として、そのChatGPTプロジェクトで対象としている開発リポジトリです。複数ある場合はChatGPTが確認します。

**Q. URLだけでコードが書き換わるのか**  
A. いいえ。意図しない変更を避けるため、まず現状診断と計画まで進めます。後続の「適用して」が変更の合図です。
